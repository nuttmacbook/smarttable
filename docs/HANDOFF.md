จัดทำโดย เปา (หัวหน้าแผนกพัฒนาเว็บ) · ปรับให้ตรงสภาพ production ณ วันที่ 13 ต.ค. 2569 (T56 / คำสั่งบอส O20)
**ไฟล์นี้ไม่มี secret/key/ค่าจากไฟล์ `.env` จริง** — ระบุชื่อตัวแปรเท่านั้น

> **อ่านก่อนทำอะไร (3 ข้อ):**

## 1. ภาพรวมและเป้าหมายระบบ

### 1.1 ใครใช้ ทำอะไร
| ผู้ใช้ | ใช้ทำอะไร |
|---|---|
| **แอดมิน/เจ้าหน้าที่ฝ่ายวิชาการ** (ล็อกอิน) | จัดการรายวิชา ครู กลุ่มเรียน ห้องเรียน แผนการเรียน; ลงตาราง (ทีละช่องหรือหลายช่อง); นำเข้า Excel/JSON; ส่งออก/พิมพ์; สร้างลิงก์แชร์; ตั้งค่าโหมดสาธารณะ |
| **ผู้ชมทั่วไป** (นักเรียน/ครู ไม่ต้องล็อกอิน ไม่ต้องมีลิงก์) | เปิดเว็บแล้วเลือกกลุ่มเรียน/ครู/ห้องเรียนจากรายการ (มีค้นหา) ดูตารางอย่างเดียว พิมพ์/ส่งออกเองได้ — เมื่อแอดมินเปิดโหมดสาธารณะ (ค่าเริ่มต้นเปิด) |
| **ผู้ถือลิงก์แชร์** (ดูอย่างเดียว) | เปิดลิงก์ `/#/view/<token>` เห็นเฉพาะขอบเขต (scope) ของลิงก์: ทั้งหมด / กลุ่มเรียน / ครู / ห้องเรียน |

เป้าหมาย: ให้เจ้าหน้าที่จัดตารางเรียนของสถานศึกษาอาชีวศึกษา **ได้โดยไม่ชนกัน** (ครู กลุ่มเรียน ห้องเรียน คาบ ชั่วโมงที่ต้องเรียน) เห็นว่าคาบไหนลงแล้ว และให้นักเรียน/ครูดูตารางของตนได้เอง

### 1.2 อิงแนวระบบ ศธ.02 ของ สอศ. และสมมติฐานที่ตั้งเอง
บอสไม่มีฟอร์ม ศธ.02 ตัวอย่างให้ และทีมค้นเว็บไม่ได้ (เครื่องมือค้นหาใช้ไม่ได้) จึงใช้ความรู้ทั่วไปของงานทะเบียน/จัดตารางของ สอศ. — **ทั้งหมดนี้เป็น "สมมติฐาน" ไม่ใช่ข้อกำหนดทางการ**:
- ข้อมูลหลัก: รายวิชา (รหัส ชื่อ ประเภท ท-ป หน่วยกิต ชม./สัปดาห์), ครูผู้สอน, กลุ่มเรียน (ระดับ ปวช./ปวส. ชั้นปี สาขา), ห้องเรียน (สถานที่), แผนการเรียน (ชุดวิชา), ตารางสอน (วัน คาบ วิชา ครู กลุ่มเรียน ห้องเรียน)
- ชม./สัปดาห์ = ทฤษฎี + ปฏิบัติ (ท+ป) ใช้เป็น "ชั่วโมงที่ต้องเรียนต่อสัปดาห์ต่อกลุ่มเรียน" ตัวเลขเท่ากันทุกกลุ่ม (ยังไม่มีค่าแยกต่อแผน/กลุ่ม)
- รหัสวิชาไม่บังคับรูปแบบ (ตัวอย่าง `20000-1101`) ตรวจแค่ไม่ซ้ำ
- ไม่ตรวจชั่วโมงสอนสูงสุดของครู และความจุห้องเทียบจำนวนนักเรียน
- ข้อมูลชุดเดียวทั้งสถานศึกษา ไม่แยกภาคเรียน (ภาคเรียน/ปีการศึกษากรอกตอนส่งออก)
- บัญชีแอดมินกำหนดที่เซิร์ฟเวอร์ผ่าน env ไม่มีหน้าสมัคร/ลืมรหัสผ่านในแอป

## 2. กติกาธุรกิจทั้งหมดที่ตกลงกับบอส (O1–O17)
อ้างอิงที่มา: O1 = เว็บตารางเรียนเริ่มต้น (T1) · O3 = กลุ่มเรียน/ห้องเรียน/ระดับ/ห้องไม่บังคับ (T10) · O4 = ตัวกรองวิชา + หลายครูต่อวิชา (T15) · O15 = ชั่วโมงบังคับ/นำเข้า/ล็อกอิน/Vercel+Upstash/พิมพ์/แผงวิชา (T29) · O16 = ย้ายโฟลเดอร์ (T39) · O17 = หลายช่อง/สาธารณะ/ค้นหา+แบ่งหน้า/พิมพ์ A4 (T40) (คำสั่งอื่นระหว่างทางเป็นงานของแผนกที่ไม่เกี่ยวกับโปรเจกต์นี้) · O20 = ตัดให้เหลือ production อย่างเดียว (T50)

### 2.1 เวลาและผังตาราง
1. **จันทร์–ศุกร์** เท่านั้น (เสาร์–อาทิตย์หยุด) · **11 คาบต่อวัน คาบละ 1 ชั่วโมง 08:00–20:00** (คาบ 1 = 08–09 … คาบ 4 = 11–12, คาบ 5 = 13–14 … คาบ 11 = 19–20)
2. **พักเที่ยง 12:00–13:00 ไม่ใช่คาบ** แสดงเป็นคอลัมน์คั่นระหว่างคาบ 4 กับ 5 ลงวิชาไม่ได้
3. **ผังหน้าตาราง ทุกมุมมองและทุกไฟล์พิมพ์/ส่งออก: คอลัมน์ = คาบ (รวมคอลัมน์พักเที่ยง) แถว = วัน จันทร์–ศุกร์** (บอสสั่งใน O3 ให้กลับด้านจากเดิม)

### 2.2 เอนทิตีและคำศัพท์ (ห้ามปนกัน)
4. **กลุ่มเรียน** (`groups`) = กลุ่มนักเรียน เช่น ปวช.1/1 (เดิมเรียก "ห้อง/ห้องเรียน" — เปลี่ยนชื่อใน O3) · **ห้องเรียน** (`rooms`) = สถานที่เรียนจริง เช่น 411, ห้องปฏิบัติการคอมพิวเตอร์ 1 · ในโมเดลข้อมูล `entry.groupId` = กลุ่มเรียน, `entry.roomId` = ห้องเรียน (ชื่อ key `rooms` ถูกนำกลับมาใช้ด้วยความหมายใหม่)
5. **ห้องเรียนเป็นตัวเลือก** — ลงคาบโดยไม่ระบุห้องได้ (ถ้าไม่ระบุ ไม่ตรวจชนห้อง)
6. **วิชา** มี 2 ประเภท: **วิชาสามัญ** (`general`) และ **วิชาชีพเฉพาะ** (`vocational`) · แต่ละวิชามี `hours` (ชม./สัปดาห์ = ท+ป) หน่วยกิต หมายเหตุ
7. **ระดับ** (`LEVELS`): `ปวช.1`, `ปวช.2`, `ปวช.3` (หลัก) และ `ปวส.1`, `ปวส.2` (คงไว้ให้ข้อมูลเดิมแปลงได้) · **กลุ่มเรียนมี 1 ระดับ · วิชาเลือก "ระดับที่เปิดสอน" ได้หลายระดับ (ต้องเลือกอย่างน้อย 1) · ลงตารางได้เฉพาะวิชาที่เปิดสอนในระดับของกลุ่มนั้น**
8. **ครูผู้สอน: 1 วิชามีครูได้ 0–n คน** (`subject.teacherIds`) · ตอนลงแต่ละคาบเลือกครูจากรายชื่อของวิชานั้น (`entry.teacherId`; วิชามีครูคนเดียวใช้คนนั้นอัตโนมัติ) · "ครูที่มีผล" ของคาบ = `entry.teacherId` ถ้ามี ไม่งั้นครูคนเดียวของวิชา ไม่งั้นไม่มี (เตือน ไม่บล็อก)
9. **แผนการเรียน** (`plans`) = ชุดวิชาของระดับหนึ่ง ใช้ผูกวิชาที่ต้องเรียนให้กลุ่มเรียนทีเดียว (`group.applyPlan` โหมด replace/merge; ไม่ลบคาบเดิม; วิชาที่ระดับไม่ตรงกลุ่มถูกข้ามและรายงาน) · `group.subjectIds` = วิชาที่กลุ่มต้องเรียน

### 2.3 กฎกันชนและชั่วโมง (`js/scheduler.js` — ใช้ทั้งไคลเอนต์และเซิร์ฟเวอร์)
10. ชนที่ **บล็อก** (ลงไม่ได้ มีข้อความเหตุผลภาษาไทย) — ชนิด conflict:
    - `group` กลุ่มเรียน+วัน+คาบ เดียวกันมีได้ 1 รายการ
    - `teacher` ครู (ที่มีผล) คนเดียวสอนสองกลุ่มเรียนวัน+คาบเดียวกันไม่ได้ · ครูต่างคนของวิชาเดียวกันต่างกลุ่มคาบเดียวกันได้
    - `classroom` ห้องเรียนเดียวกัน วัน+คาบเดียวกัน ถูกกลุ่มเรียนอื่นใช้ไม่ได้
    - `level` ระดับของกลุ่มไม่อยู่ในระดับที่วิชาเปิดสอน
    - `lunch` ช่วงพักเที่ยง · `invalid` ข้อมูลไม่ถูกต้อง (วัน/คาบ/อ้างอิงผิด/ครูไม่อยู่ในรายการของวิชา)
    - `hours` ชั่วโมงเกิน (ข้อ 12)
11. **เรียนรวม (วิชาสามัญเดียวกันหลายกลุ่ม ลงซ้ำคาบเดียวกันได้)** — `canMerge`: วิชา id เดียวกัน **และ** ประเภทสามัญ → ข้ามการชนครู/ห้องเรียนระหว่างกลุ่ม (ครูคนเดียวกันเรียนรวมได้ ใช้ห้องเดียวกันได้) · **วิชาชีพเฉพาะเรียนรวมไม่ได้**
12. **ชั่วโมงเกินถูกบล็อกจริง (ไม่ใช่แค่เตือน)** — นับจำนวนคาบของ (กลุ่มเรียน + วิชา) ต้องไม่เกิน `subject.hours` (เรียนรวมข้ามกลุ่มนับแยกต่อกลุ่ม) · ใช้กับ: ลง, ย้าย (ไม่นับคาบของตัวเอง), นำเข้า JSON/Excel, ลด `hours` ของวิชาให้ต่ำกว่าที่ลงแล้ว, และตรวจซ้ำที่เซิร์ฟเวอร์ทุก op
    - **ข้อมูลเดิมที่เกินอยู่แล้ว (legacy)** โหลดได้ไม่พัง (`legacyViolations`) แต่ op อื่นที่ไม่ใช่การแก้ถูกบล็อกจนกว่าจะแก้ (ลบ/ย้ายคาบที่เกินได้) · นำเข้าไฟล์ที่เกินถูกปฏิเสธ เว้นแต่เลือก "ตัดคาบส่วนเกิน" (`trimOverHours` — ตัดคาบที่ลงทีหลังสุด แล้วรายงานรายการที่ถูกตัดครบ)
13. คำเตือน (ไม่บล็อก): วิชายังไม่มีครู · วิชามีหลายครูแต่ยังไม่เลือกครูของคาบ · วิชาไม่อยู่ในรายการวิชาของกลุ่ม (ถ้ากลุ่มมี `subjectIds` อยู่)

### 2.4 หน้าลงตาราง
14. **แผงด้านข้างรายวิชาของกลุ่ม** (เลือกกลุ่มแล้วขึ้น): ต้องเรียน / จัดแล้ว / เหลือ + ครู · เรียงวิชาที่เหลือขึ้นก่อน · ครบแล้ว = "เสร็จ ✓" · เกิน (legacy) = แดง · คลิกวิชาในแผง = เลือกเป็น "วิชาที่กำลังลง" แล้วคลิกช่องลงได้เลย
15. **ตัวกรอง "แสดงเฉพาะวิชาที่ลงได้"** ในตัวเลือกวิชา — ติ๊ก = ซ่อนวิชาที่ลงไม่ได้ (ระดับไม่ตรง ชนครู/ห้อง ชั่วโมงเต็ม ฯลฯ) ค่าเริ่มต้นติ๊ก จำค่าไว้ในที่เก็บของเบราว์เซอร์ (Web Storage คีย์ `timetable.ui.onlyPlaceable` — เป็นค่าตั้งการแสดงผล ไม่ใช่ข้อมูลตาราง)
16. **เลือกหลายช่องรวดเดียว** (โหมดเลือกหลายช่อง): ตั้งวิชา/ครู/ห้องครั้งเดียว แล้วเลือกช่องด้วยคลิกสะสม / ลากต่อเนื่อง / Shift+คลิกช่วง / ปุ่มช่วงบนทัช (Esc ล้าง) · กด "ลงตาราง" → ตรวจล่วงหน้า (`dryRun`) → ถ้าบางช่องลงไม่ได้ขึ้นรายช่องพร้อมเหตุผลให้เลือก "ลงเฉพาะที่ลงได้" หรือ "ยกเลิกทั้งชุด" · โหมดลบหลายช่อง (confirm ระบุจำนวน) · **op เดียว atomic (`entry.placeMany`/`entry.removeMany`) = CAS ครั้งเดียว = version +1 · เพดาน 200 ช่องต่อครั้ง** · ตรวจตามลำดับ (วัน, คาบ) โดยนับรายการก่อนหน้าในชุดด้วย (ชั่วโมงเหลือ H → ผ่าน H ช่องแรก) · ช่องซ้ำในชุด = กลุ่ม+วัน+คาบ

### 2.5 นำเข้า / ส่งออก / ค้นหา / พิมพ์
17. **นำเข้า Excel (.xlsx)** 5 ชีตหัวคอลัมน์ภาษาไทยตายตัว (`รายวิชา`, `ครูผู้สอน`, `ห้องเรียน`, `กลุ่มเรียน`, `แผนการเรียน`; ชีตเทมเพลตมี `วิธีใช้` เพิ่มซึ่งถูกข้าม) · **merge ตามคีย์** (รหัสวิชา / ชื่อครู / ชื่อห้อง / ชื่อกลุ่ม / ชื่อแผน): ตรงกัน = อัปเดตช่องที่กรอก (ว่าง = ไม่ทับ) ไม่ตรง = เพิ่มใหม่ · **ไม่ลบอะไร** · **รายงานแถวผิดก่อนยืนยัน** (ชีต/แถว/คอลัมน์/ระดับ error-warning-info) · มี error ≥1 = ยืนยันไม่ได้ · atomic ทั้งก้อน · มีปุ่มดาวน์โหลดเทมเพลต · จำกัด ≤5 MB, ≤5,000 แถว/ชีต, เซลล์ ≤500 ตัวอักษร · ตรวจไฟล์ zip ก่อนอ่าน (`zip-guard`: กัน zip bomb/macro/path traversal) · **เซิร์ฟเวอร์ไม่ parse .xlsx** (ไคลเอนต์อ่านแล้วส่ง rows ให้ตรวจซ้ำ)
18. **นำเข้า/ส่งออก JSON** (หน้า "ข้อมูล") — migrate ไฟล์ v1–v4 → v5 ให้อัตโนมัติ (นี่คือทางย้ายข้อมูลเดิมจากระบบรุ่นเก่า); ก่อนแทนที่ข้อมูลทั้งก้อนสำรอง JSON ฝั่งไคลเอนต์ + snapshot ฝั่งเซิร์ฟเวอร์
19. **ส่งออก/พิมพ์ .xlsx และ .pdf** รายครู / รายห้องเรียน / รายกลุ่มเรียน เลือกได้: รายการเดียว / หลายรายการ / ทั้งหมดของประเภท / ทุกประเภท → **ไฟล์รวม** (xlsx = 1 ชีตต่อรายการ ชื่อชีต ≤31 ตัวอักษรไม่ซ้ำ; pdf = **1 หน้า A4 แนวนอนต่อรายการ**) · ภาคเรียน/ปีการศึกษากรอกในกล่องส่งออก (ไม่เก็บในระบบ)
20. **ค้นหา/กรอง + แบ่งหน้า ทุกรายการ**: แผนการเรียน กลุ่มเรียน รายวิชา ครู ห้องเรียน ตัวเลือกวิชา แผงวิชา ลิงก์แชร์ รายงานนำเข้า กล่องส่งออก หน้าสาธารณะ และ select ที่ตัวเลือกอาจเกิน ~25 รายการ · ค้นไทยได้ ไม่สนตัวพิมพ์ (ทุกคำต้องตรง) · กรองตามระดับ/ประเภท · แบ่งหน้า **25/50/100** · จำค่าค้นหา/ตัวกรอง/ขนาดหน้าไว้ในที่เก็บของเบราว์เซอร์ (คีย์ `tt.ui.list.<ชื่อ>`; ผู้ชมใช้ที่เก็บระดับแท็บ; logout ล้าง; ค่าที่อ่านกลับถือเป็นข้อมูลไม่เชื่อถือและถูกตรวจ) · ออกแบบให้ค้นหา 500–5,000 รายการเร็วกว่า 50 ms (วัดไว้ตอนพัฒนา — ปัจจุบันไม่มีชุดวัดเหลือในโปรเจกต์)
21. **พิมพ์ A4 แนวนอน อ่านออกเมื่อพิมพ์ขาวดำ**: ข้อความในช่องไม่ล้นกรอบ (ลดฟอนต์ตามความยาว ตัดบรรทัด/`…` + legend ชื่อเต็ม); แยกชนิดช่องโดยไม่พึ่งสีอย่างเดียว: **สามัญ = พื้นอ่อน + ○ "ส"; วิชาชีพเฉพาะ = พื้นเข้ม + ลายทแยง + ตัวหนา + ● "ช"; เรียนรวม = ขอบคู่ + "ร"; พักเที่ยง = ลายถี่ + ข้อความ "พัก/เที่ยง"; ว่าง = ขาว** (ตรงกันทั้งจอ พิมพ์จากเบราว์เซอร์ `@media print` และ PDF)

### 2.6 สิทธิ์ ล็อกอิน และการเข้าชม
22. **แอดมินเท่านั้นแก้ได้** — UI ซ่อนปุ่มแก้ และ **เซิร์ฟเวอร์ปฏิเสธการเขียนทุกกรณีที่ไม่มี session แอดมิน** (สิทธิ์จริงตัดสินที่เซิร์ฟเวอร์เสมอ)
23. **โหมดสาธารณะ** (แอดมินเปิด/ปิดที่หน้า "ตั้งค่า"; **ค่าเริ่มต้นเปิดตามบอสสั่ง**): ผู้ชมทั่วไปดูตารางทั้งสถานศึกษาแบบอ่านอย่างเดียว ไม่ต้องล็อกอิน · เขียนไม่ได้ · ปิดโหมด = ผู้ชมเห็นหน้า "ผู้ดูแลปิดการเข้าชมสาธารณะ"
24. **ซ่อนชื่อครูในโหมดสาธารณะ (PDPA)** — `hideTeacherNames`: ค่าเริ่มต้น `null` = "ยังไม่ยืนยัน" **ถือเป็นซ่อน** (`effectiveHide = hideTeacherNames !== false`) · ผู้ชมเห็นชื่อครูได้เมื่อแอดมินตั้ง `false` เอง (มีแบนเนอร์เตือนแอดมินจนกว่าจะบันทึกตั้งค่า) · ซ่อนที่ **เซิร์ฟเวอร์** (response ไม่มี `teachers`, `teacherIds`, `teacherId`, `note`, `dept`, `plans`) ไม่ใช่แค่ UI · ถ้าการตั้งค่าเสีย/Redis ล้ม = **fail-closed** (ซ่อน หรือ 503) ไม่ตกไปเป็นแสดงชื่อ
25. **ลิงก์แชร์แบบดูอย่างเดียว** (ยังคงอยู่ใช้ได้เมื่อปิดโหมดสาธารณะหรืออยากจำกัด scope): scope `all` | `group:<id>` | `teacher:<id>` | `room:<id>` · สร้างได้หลายลิงก์ · **เพิกถอน/สร้างใหม่ได้** · token สุ่ม 256 บิต เก็บฝั่งเซิร์ฟเวอร์เป็น SHA-256 เท่านั้น แสดงเต็มครั้งเดียว · ส่งทาง header `X-Share-Token` เท่านั้น (ไม่ใส่ใน URL ของ API; URL หน้าเว็บ `/#/view/<token>` ใช้ fragment) · **scope `all` หมดอายุ 90 วันโดยค่าเริ่มต้น** (ต่ออายุด้วยสร้างใหม่) · ลบกลุ่ม/ครู/ห้อง = ลิงก์ที่ชี้เอนทิตีนั้นถูกเพิกถอนอัตโนมัติ (แม้สร้าง id เดิมใหม่ ลิงก์เก่าก็ไม่กลับมา)
26. **บัญชีแอดมิน** กำหนดใน env `ADMIN_ACCOUNTS` (หลายบัญชีได้ สิทธิ์เท่ากัน) · username **ไม่แยกตัวพิมพ์** · เปลี่ยนรหัส/เพิ่ม/ลบ = แก้ env แล้ว redeploy (session เดิมของบัญชีนั้นใช้ไม่ได้ทันที) · session หมดอายุ idle 2 ชม. / absolute 12 ชม.

### 3.5 โมเดลข้อมูลและเวอร์ชัน migration
```
state (version 4) = {
  version: 4,
  subjects: [{ id, code, name, type:'general'|'vocational', credits, hours, theory?, practice?, teacherIds:[...], levels:[...≥1], note }],
  teachers: [{ id, name, dept }],
  groups:   [{ id, name, level, major, subjectIds:[...], planId|null }],     // กลุ่มเรียน
  rooms:    [{ id, name, building?, capacity?, note }],                       // ห้องเรียน (สถานที่)
  plans:    [{ id, name, level, subjectIds:[...], note }],
  entries:  [{ id, groupId, day:1..5, period:1..11, subjectId, roomId|null, teacherId|null }]
}
```
- id: `[A-Za-z0-9_-]{1,64}` และห้ามเป็นชื่อสงวนของ `Object.prototype` (`__proto__`, `constructor` ฯลฯ) — ในโค้ดห้ามใช้ object ธรรมดาเป็นดัชนีด้วย id/ชื่อ (ใช้ `Map`/`Object.create(null)` + `Object.hasOwn`)
- ข้อความ: ไม่มีอักขระควบคุม/กำกับทิศทาง/zero-width; ชื่อ/รหัส ≤200 ตัวอักษร ฟิลด์อื่น ≤500
- **ประวัติเวอร์ชัน:** v1 (เดิม `rooms`=กลุ่มเรียน) → v2 (`groups` + `rooms`=ห้องเรียน + `levels`) → v3 (`teacherIds`, `entry.teacherId`) → v4 (`plans`, `group.subjectIds/planId`) → v5 (`state.levels` ระดับที่แอดมินกำหนดได้ + ops `level.add/rename/remove/move`) · `migrateState` ต่อโซ่และ idempotent ใช้กับการนำเข้าไฟล์ JSON และ `/api/migrate` (ไฟล์ที่ไม่มี `version` ถือเป็น v1) — **รุ่นเก่าเคยเก็บข้อมูลไว้ในเบราว์เซอร์ ปัจจุบันระบบไม่อ่านที่เก็บนั้นแล้ว ผู้ใช้ต้องส่งออกเป็นไฟล์ JSON จากรุ่นเก่าแล้วนำเข้า**
- **ค่าตั้งนอก state** (Redis `tt:settings`): `{ publicMode:{ enabled:true, hideTeacherNames:null|true|false }, confirmedAt, updatedAt, updatedBy }` + ตัวนับ `revision` (ไม่ขยับ version ของตาราง)

## 4. สถาปัตยกรรม

### 4.1 ภาพรวม
- **Frontend:** HTML + CSS ธรรมดา (`css/style.css`, **ไม่ใช้ Tailwind**) + **vanilla JavaScript แบบ ES modules** (ไม่มี framework) แพ็กด้วย **Vite 8** · SPA ใช้ hash router · ฟอนต์ Sarabun ฝังผ่าน `@fontsource/sarabun`
- **Backend:** **Vercel Functions** (Node, ESM) ใน `api/` + **Upstash Redis** (REST) เป็นฐานข้อมูล · ไม่มีเซิร์ฟเวอร์อื่น
- **ที่เก็บข้อมูลมีทางเดียว:** เซิร์ฟเวอร์ (ผ่าน `api/`) — ไม่มีโหมดทดลองที่เก็บในเบราว์เซอร์ ไม่มี API จำลอง ไม่มีข้อมูลตัวอย่างในแอป · เบราว์เซอร์เก็บเฉพาะค่าตั้งการแสดงผล (คีย์ `timetable.ui.onlyPlaceable`, `tt.ui.list.*`)
- **หลักการใหญ่:** กฎธุรกิจอยู่ในโมดูล pure ที่ **ใช้ร่วมกันทั้งไคลเอนต์และเซิร์ฟเวอร์** (`scheduler.js`, `store.js`, `ops.js`, `importer.js`, `validate.js`) → ไคลเอนต์ทำนายผล เซิร์ฟเวอร์ตรวจซ้ำและตัดสินจริง

### 4.2 การเขียนข้อมูล
1. UI ทำ op ผ่าน `storage-adapter` → `POST /api/op {op, baseVersion}`
2. เซิร์ฟเวอร์โหลด state → `applyOp` (ตัวเดียวกับไคลเอนต์) → ตรวจ `validateAll` (รวมชั่วโมง) → เขียนด้วย **Lua EVAL แบบ compare-and-set**: ถ้า `tt:v == baseVersion` เขียนทุก key ที่เปลี่ยนแล้ว `INCR tt:v` ในสคริปต์เดียว ไม่ตรง → **409** (กันแอดมินหลายคนเขียนทับกัน; ไคลเอนต์ดึงข้อมูลใหม่/ทำนายซ้ำ)
3. op ทำลายล้าง (replace/trim/migrate force) ถ่าย **snapshot** (เก็บ 5 ชุด หมดอายุ 30 วัน) ใน CAS เดียวกัน · ทุกการเขียนมี **audit** (≤500 รายการ; ไม่มี secret)
4. ข้อมูลเก็บเป็น key แยก: `tt:subjects` `tt:teachers` `tt:groups` `tt:rooms` `tt:plans` `tt:entries:<groupId>` (shard ต่อกลุ่ม เลี่ยงเพดานคำขอ 1 MB) + `tt:v` `tt:meta`

### 4.3 ความปลอดภัย (สรุป — รายละเอียดที่ `docs/API.md`, `docs/DEPLOY.md`)
รหัสผ่าน **scrypt** (N=2^15, r=8, p=1, ตั้ง `maxmem`) + `timingSafeEqual` · คุกกี้ `__Host-tt_session` `HttpOnly; Secure; SameSite=Lax` · session ใน Redis ผูกบัญชี+เวอร์ชันรหัสผ่าน (เปลี่ยนรหัส/ลบบัญชีใน env = session ตาย) · **CSRF:** JSON + `X-Requested-With: tt` + ตรวจ Origin/`Sec-Fetch-Site` กับ `ALLOWED_ORIGINS` · **rate limit** login 4 ระดับ (ก่อนเรียก scrypt) / ผู้ดู 120/นาที/IP / สาธารณะ 300/นาที/IP · token แชร์เก็บเป็นแฮชเท่านั้น · CSP `script-src 'self'` (ไม่มี inline handler ทั้งแอป) + HSTS/nosniff/DENY/no-referrer · ทุกค่าจากข้อมูลผ่าน `esc()` · ไม่มี secret ใน bundle (build ล้มถ้าตั้ง `VITE_*` ที่ชื่อเหมือนความลับ)

ทำทุกคำสั่งหลัง `cd company/project/timetable`

| ต้องการ | คำสั่ง |
|---|---|

| ดูผล build | `npm run preview` (เปิดหน้าเว็บอย่างเดียว — ต้องมี `api/` จริงอยู่ด้วยจึงใช้งานได้ ระบบไม่มีโหมดที่ทำงานโดยไม่มีเซิร์ฟเวอร์) |

### 5.1 ตัวแปรแวดล้อม (ชื่อเท่านั้น — ไม่ใส่ค่า; ดูแม่แบบที่ `.env.example`)
- **ฝั่งเซิร์ฟเวอร์ (ตั้งบน Vercel; ห้ามขึ้นต้น `VITE_`):** `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` (หรือชุดที่ Vercel Upstash integration สร้างให้: `KV_REST_API_URL`, `KV_REST_API_TOKEN` — ใช้เมื่อไม่ตั้งชุด `UPSTASH_*` เลย ไม่ผสมข้ามชุด; รายละเอียดใน `docs/DEPLOY.md` ข้อ 2.1), `SESSION_SECRET` (สุ่ม ≥32 ไบต์), `ADMIN_ACCOUNTS`, `ALLOWED_ORIGINS` · ไม่บังคับ: `UPSTASH_REDIS_REST_READONLY_TOKEN` (หรือ `KV_REST_API_READ_ONLY_TOKEN`), `PUBLIC_RATE_LIMIT`
- **ฝั่งหน้าเว็บ (Vite):** ไม่ต้องตั้งตัวแปรใดเลย · ห้ามตั้งตัวแปรขึ้นต้น `VITE_` ที่เป็นความลับ (build ล้ม)
- **แยก env Production กับ Preview/Development** (คนละฐานข้อมูล คนละ `SESSION_SECRET` คนละบัญชีแอดมิน) และเปิด Deployment Protection ให้ Preview
- ข้อควรระวัง `$` ในแฮช: บน Vercel วางค่าตรง ๆ ในช่อง Value; ถ้าใช้ไฟล์ `.env` ที่ Vite/`vercel dev` อ่าน ต้อง escape เป็น `\$` (การครอบ single/double quote **ไม่ช่วย**)

## 6. สถานะปัจจุบัน

### 6.1 สิ่งที่เคยตรวจแล้วก่อนเปาตัดชุดทดสอบออก (ระดับ node / DOM จำลอง / Redis จำลองในหน่วยความจำ)
- ก่อนลบ: ชุดทดสอบอัตโนมัติผ่านครบ (649 ข้อ) และ `vite build` ผ่าน · ผู้ทดสอบและผู้ตรวจความปลอดภัยของทีมตรวจครบทุกข้อของบอสแล้ว ไม่เหลือข้อวิกฤต/สูง/กลาง · ภาพ PDF เรนเดอร์จริงทั้งสีและระดับเทาเคยตรวจ: พอดี 1 หน้า A4 ข้อความไม่ล้น สระ/วรรณยุกต์ไทยถูก แยกชนิดช่องในเทาได้
- **ผลเหล่านี้เป็นของสภาพก่อนลบเท่านั้น** — หลังลบ ชุดทดสอบ รายงาน และภาพตัวอย่างอยู่ในสำรอง `company/backup-timetable-full-2026-10-13/` ไม่ได้อยู่ในโปรเจกต์ production · ถ้าแก้โค้ดต่อ ต้องเขียนชุดทดสอบใหม่หรือกู้จากสำรอง (ข้อ 8)

### 6.2 ยังไม่ได้ทดสอบจริง (ต้องรู้ — อย่าสรุปว่าเสร็จสมบูรณ์)
1. **Upstash/Vercel จริงทั้งหมด:** adapter `@upstash/redis` ใน `server/redis.js` **ไม่เคยรันกับ Upstash จริง**; สคริปต์ Lua CAS (`EVAL`: RENAME/PERSIST/HSET/LPUSH/LTRIM, ชนิดค่าที่คืน) ไม่เคยรันจริง — เคยทดสอบกับ Redis จำลองในหน่วยความจำที่ทำให้พฤติกรรมเหมือนกัน (ซึ่งไม่ใช่ของจริง); เพดานคำขอ 1 MB; `maxDuration`; ข้ามอินสแตนซ์ serverless; read-only token; header IP ของ Vercel (`x-vercel-forwarded-for`/`x-real-ip` ตามเอกสาร); ETag/304 ผ่าน CDN และ header `no-cache` ของ `/api/public` (regex `source` ใน `vercel.json`); คุกกี้ `Secure`/`__Host-` บน https
2. **เบราว์เซอร์จริงทั้งหมด:** คลิก/ลากด้วยเมาส์และนิ้ว/ทัช/Shift-คลิก, CSS จริง, ลิ้นชักแผงบนจอแคบ (<1100px) และจอ 768px, แถบแท็บล่าง · **CSP + Web Worker ของ `read-excel-file` ภายใต้ `worker-src blob:` เป็นข้อสันนิษฐาน**
3. **พิมพ์จริง:** `@media print`/`@page A4 landscape` เห็นเฉพาะระดับโค้ด; ไม่เคยพิมพ์กระดาษ; ฟอนต์ 6pt บนกระดาษจริง; ไม่เคยเปิด PDF ในโปรแกรมอ่านจริง; ส่งออก PDF ผ่านหน้าเว็บจริงในเบราว์เซอร์ (โหลดฟอนต์ `/fonts/*.woff` ภายใต้ CSP) ยังไม่ได้ลอง
4. **Excel จริง:** ไฟล์ .xlsx ที่ส่งออก/เทมเพลต/รายงานนำเข้า ยังไม่เคยเปิดใน Excel/LibreOffice (เคยตรวจด้วยการแตกไฟล์ + อ่านกลับ)
5. **Node 22** (ที่ Vercel ใช้ตาม `engines`): เคยรันกับ **Node v26** เท่านั้น · `vercel dev` กับค่า `\$` ใน `.env` · โหมด TTY ของ `hash-password` · เวลาตอบ login เท่ากันจริงของ username ที่ไม่มี (วัดหยาบเท่านั้น)
6. **ไม่เหลือชุดทดสอบอัตโนมัติใน production** — การแก้โค้ดจากนี้ไม่มีตาข่ายกันถดถอย (ข้อ 8.1)
7. `zip-guard` ตรวจโครงสร้างไฟล์ ไม่ใช่การสแกนมัลแวร์ · การคัดลอกข้อความจาก PDF ข้ามบรรทัดไม่เป็นธรรมชาติ (ข้อความวางทีละบรรทัด)

### 6.3 ความเสี่ยงที่รับไว้
- ผู้โจมตีที่กระจายหลาย IP ทำให้แอดมินล็อกอินไม่ได้ **ชั่วคราว** (≤15 นาที) ได้ (ตัวนับ username รวมทุก IP / ทั้งระบบ) — วิธีปลดล็อกอยู่ใน `docs/DEPLOY.md` (ต้องเข้า Upstash console ได้)
- แอดมินทุกคนสิทธิ์เท่ากัน ไม่มีหน้าจัดการบัญชี · admin ของโปรเจกต์ Vercel และผู้เข้า Upstash console มีสิทธิ์สูงสุดเหนือข้อมูล
- **ถ้าแอดมินตั้ง `hideTeacherNames:false` ชื่อครู + ตารางสอนทั้งสถานศึกษาจะเปิดสาธารณะถาวรจนกว่าจะตั้งกลับ** (PDPA) · ช่อง `note` ที่เป็นข้อความอิสระระบบลบชื่อครูให้ไม่ได้ (ตอนซ่อนชื่อ ระบบตัด `note` ทิ้งทั้งหมดใน response สาธารณะ)
- ลิงก์แชร์ scope `all` เห็นชื่อครู (หมดอายุ 90 วัน)
- ไม่มี undo ของการลบ/ย้ายคาบ (มีเฉพาะ snapshot ฝั่งเซิร์ฟเวอร์ก่อน op ทำลายล้าง และสำรอง JSON ฝั่งไคลเอนต์ก่อนแทนที่ข้อมูลทั้งก้อน)

## 10. สไตล์ มาตรฐานงาน และรายการเอกสารที่ควรอ่าน

### 10.1 มาตรฐานที่ทีมใช้ (ทำตามต่อไป)
- **ภาษาไทย** ทั้ง UI ข้อความเหตุผลที่ชน เอกสาร และบันทึก
- **สเปกก่อนลงมือ:** เขียน/ล็อกสัญญา (ลายเซ็นฟังก์ชัน รูป response ชื่อ op) ใน `docs/SPEC.md` ก่อนแจกงาน เพื่อให้ทีมทำขนานกันได้ · `docs/SPEC.md` ปัจจุบันเป็นฉบับรวมสภาพล่าสุด (ไม่ซ้อนเป็นชั้นเหมือนรุ่นก่อน)
- **โมดูล pure ใช้ร่วมไคลเอนต์/เซิร์ฟเวอร์** ไม่ copy · เซิร์ฟเวอร์ตรวจซ้ำทุกอย่าง (UI เป็นแค่ความสะดวก)
- **ไม่ใช้ object ธรรมดาเป็นดัชนีด้วย id/ชื่อ** (`Map` หรือ `Object.create(null)` + `Object.hasOwn`) และ id ห้ามเป็นชื่อสงวน
- **ไม่มี inline handler** (`onclick=` ฯลฯ) — ใช้ `data-*` + event delegation (รองรับ CSP `script-src 'self'`) · ทุกค่าจากข้อมูลผ่าน `esc()` ตัวเดียว
- **ไม่มี secret ใน client/bundle/log** · ห้าม `VITE_` นำหน้าค่าลับ
- **ไม่เพิ่ม dependency โดยไม่จำเป็น** — ถ้าจำเป็นต้องแจ้งเหตุผล ปักเวอร์ชัน ใส่ตารางข้อ 4.4
- **รายงานตรงไปตรงมา:** ทุกงานส่งมอบต้องบอกว่า "อะไรทดสอบจริง / อะไรตรวจจากโค้ด / อะไรไม่ได้ทดสอบ" ห้ามอ้างว่าผ่านถ้าไม่ได้รัน
- **ขั้นตอนทีม (ที่เคยใช้):** นักพัฒนา → ผู้ทดสอบ (แบงค์) ตรวจ → ผู้ตรวจความปลอดภัย (ออม) ตรวจโดยไม่แก้โค้ด (รายงานแล้วให้เจ้าของไฟล์แก้) → เปาตรวจและ deliver · ห้ามแก้ไฟล์ที่เป็นของคนอื่น แจ้งเจ้าของ
- ผู้ลงมือหลัก: โดม (logic/ops/importer), ฟ้า (หน้าเว็บ), มิ้นท์ (design/css), ไนน์ (api/Vercel/Upstash), อิงค์ (ส่งออก xlsx/pdf), แบงค์ (ทดสอบ), ออม (security), แทน (ทดสอบ api)
