# คู่มือ deploy ระบบตารางเรียนขึ้น Vercel + Upstash Redis

คู่มือนี้ทำตามทีละข้อตั้งแต่ศูนย์จนระบบใช้งานจริง · รายละเอียด request/response ของ API อยู่ที่ [`API.md`](API.md)

> **สถานะตามจริง:** ขั้นตอนทั้งหมดเขียนจากเอกสารของ Vercel/Upstash และจากการทดสอบตรรกะในเครื่องก่อนตัดตัวช่วยทดสอบออก (ใช้ Redis จำลองที่ตอนนี้ไม่อยู่ในโค้ดแล้ว) — **ตัวเชื่อม Upstash และสคริปต์ Lua ยังไม่เคยรันกับ Upstash จริง และยังไม่เคย deploy ขึ้นระบบจริงเลย** ดูหัวข้อ "สิ่งที่ยังไม่ได้ยืนยัน" ท้ายเอกสาร ถ้าขั้นไหนไม่ตรงกับที่เห็นบนหน้าจอ ให้ยึดหน้าจอและแจ้งผู้ดูแลโค้ด

## 0. ภาพรวมว่าระบบทำงานอย่างไร
- **หน้าเว็บ** = Vite (JavaScript ล้วน) build ออกโฟลเดอร์ `dist/` · **ฝั่งเซิร์ฟเวอร์** = Vercel Functions ในโฟลเดอร์ `api/` (11 ตัว; แพ็กเกจฟรี Hobby จำกัด 12) · โค้ดร่วมอยู่ที่ `server/`
- **ข้อมูลจริง** เก็บใน **Upstash Redis** เท่านั้น (ผ่าน `api/`) ไม่มีข้อมูลในเบราว์เซอร์
- **แอดมิน** เข้าสู่ระบบด้วย username/รหัสผ่านแล้วแก้ข้อมูลได้ · **ผู้ชมทั่วไป** เปิดเว็บดูตารางได้โดยไม่ต้องล็อกอิน (โหมดสาธารณะ) แต่แก้ไขอะไรไม่ได้ · **ลิงก์แชร์** `/#/view/<token>` ให้ดูเฉพาะกลุ่ม/ครู/ห้องที่เลือก
- รหัสผ่านแอดมินไม่เก็บในฐานข้อมูล — เก็บเป็น **แฮช** ในตัวแปร `ADMIN_ACCOUNTS` ของ Vercel

## 1. สิ่งที่ต้องมีก่อนเริ่ม
- บัญชี [Vercel](https://vercel.com) และ [Upstash](https://upstash.com) (แพ็กเกจฟรีเริ่มต้นได้ — ตรวจโควตาจริงของแต่ละเจ้าเองที่หน้าราคา ผู้เขียนไม่ได้ตรวจ)
- เครื่องที่ติดตั้ง **Node.js 22** (โปรเจกต์กำหนด `22.x`) และ npm — ใช้สร้างแฮชรหัสผ่านและ build ตรวจก่อนขึ้นจริง
- โฟลเดอร์โปรเจกต์ของระบบตารางเรียน (โฟลเดอร์ที่มีไฟล์ `package.json`, `api/`, `js/`, `vercel.json`) — เรียกว่า **โฟลเดอร์โปรเจกต์** ในคู่มือนี้ · **ไม่ใช่** `crypto-matrix/`
- ในโฟลเดอร์โปรเจกต์รัน `npm install` หนึ่งครั้ง

## 2. สร้างฐานข้อมูล Upstash Redis
1. เข้า [console.upstash.com](https://console.upstash.com) → **Redis** → **Create Database**
2. ตั้งชื่อ (เช่น `timetable-prod`) · Type = **Regional** · **Region = Singapore (`ap-southeast-1`)** — `vercel.json` ตั้งฟังก์ชันไว้ที่ `sin1` (สิงคโปร์) ใช้ภูมิภาคใกล้กันจะตอบเร็ว
3. สร้างเสร็จเปิดหน้าฐานข้อมูล → แท็บ **REST API** (ไม่ใช่แท็บที่แสดง `redis://…`) แล้วคัดลอก 2 ค่า:
   - `UPSTASH_REDIS_REST_URL` (ขึ้นต้น `https://…upstash.io`)
   - `UPSTASH_REDIS_REST_TOKEN` (สตริงยาว)
   - ถ้าหน้านั้นมีตัวเลือก **Read-only Token** ให้คัดลอกเก็บไว้ด้วย (ไม่บังคับ แต่แนะนำ — ใช้เป็น `UPSTASH_REDIS_REST_READONLY_TOKEN`)
4. **ทำฐานข้อมูลที่ 2 สำหรับทดสอบ (Preview)** ด้วยวิธีเดียวกัน ถ้าจะใช้ Preview — ห้ามใช้ฐานเดียวกับของจริง (ข้อ 5)
5. เก็บค่าเหล่านี้ไว้ในที่ปลอดภัย (ตัวจัดการรหัสผ่าน) อย่าส่งทางแชต/อีเมล และอย่าบันทึกลงไฟล์ในโปรเจกต์

## 3. สร้างความลับของเซิร์ฟเวอร์

### 3.1 `SESSION_SECRET` (กุญแจของเซสชัน)
รันในเทอร์มินัล แล้วคัดลอกผลลัพธ์ทั้งบรรทัด:
```
node -e "console.log(require('node:crypto').randomBytes(48).toString('base64url'))"
```
- ต้องยาวอย่างน้อย **32 ไบต์** และสุ่ม · ถ้าขาดหรือสั้นไป การเข้าสู่ระบบจะตอบ 500
- หน้าที่: เป็นกุญแจ HMAC ของเซสชันใน Redis — คนที่อ่าน Redis ได้อย่างเดียวจึงสร้างคุกกี้ที่ใช้ได้เองไม่ได้
- **เปลี่ยนค่านี้ = ทุกคนที่ล็อกอินอยู่หลุดทันที** (ใช้เป็นวิธี "ออกจากระบบทุกเครื่อง")
- Production กับ Preview ใช้ **คนละค่า**

### 3.2 `ADMIN_ACCOUNTS` (บัญชีแอดมิน) — สร้างทีละขั้น
1. เปิดเทอร์มินัลในโฟลเดอร์โปรเจกต์
2. รัน `npm run hash-password -- <username>` เช่น `npm run hash-password -- admin`
   - `username`: ใช้ได้เฉพาะ `A-Z a-z 0-9 . _ -` ยาว 1–64 ตัว · **ไม่แยกตัวพิมพ์เล็ก/ใหญ่** (`Admin` = `admin` สคริปต์เก็บเป็นตัวพิมพ์เล็ก) · ห้ามช่องว่าง `:` `;` และห้ามภาษาไทย · ห้ามมีสองบัญชีที่ต่างกันแค่ตัวพิมพ์ (ระบบจะตอบ 500 กับทุกคน)
3. สคริปต์ถามรหัสผ่าน 2 ครั้ง (**ไม่แสดงตัวอักษรบนจอ**) ยาวอย่างน้อย **10 ตัวอักษร** — ใช้ประโยคยาว ๆ ที่จำง่าย เช่นชุดคำ 4 คำ
   - **ห้ามพิมพ์รหัสผ่านต่อท้ายคำสั่ง** (สคริปต์ปฏิเสธ) เพราะจะค้างใน history ของเทอร์มินัล · สคริปต์ไม่เขียนรหัสผ่านลงไฟล์ ไม่พิมพ์ซ้ำ และตรวจย้อนกลับ (แฮชแล้วตรวจกลับ) ก่อนแสดงผล
4. ผลคือหนึ่งบรรทัด หน้าตาแบบ (ตัวอย่างย่อ ไม่ใช่ค่าจริง):
   ```
   ADMIN_ACCOUNTS=admin:scrypt$32768$8$1$AbCdEf...==$GhIjKl...==
   ```
   ยาวราว 150 ตัวอักษร — **คัดลอกทั้งบรรทัด** (ระบบยอมรับทั้งแบบมีคำนำหน้า `ADMIN_ACCOUNTS=` และแบบเฉพาะ `admin:scrypt$…`)
5. **หลายแอดมิน:** สร้างแฮชทีละคน แล้วต่อกันในค่าเดียวด้วย `;` เช่น `admin:scrypt$…;teacher2:scrypt$…`
6. **เครื่องหมาย `$` ในแฮช:**
   - ที่ช่อง **Value ของ Vercel วางตรง ๆ ได้เลย ไม่ต้องใส่เครื่องหมายคำพูด** (ทางหลัก)
   - ถ้าเอาไปใส่ในไฟล์ `.env` ที่ Vite อ่าน มันจะขยาย `$ชื่อ…` เป็นตัวแปรแล้วทำให้แฮชเพี้ยน (ทดสอบแล้ว: ไม่ครอบ, ครอบ `'…'`, ครอบ `"…"` เพี้ยนหมด; เกิดกับราว 70% ของแฮช จึง "บางครั้งไม่เพี้ยน" ซึ่งพลาดง่าย) — ที่ใช้ได้จริงคือ escape ทุก `$` เป็น `\$` (สคริปต์พิมพ์รูปนี้ให้แยกในเทอร์มินัล ใช้เฉพาะในไฟล์ `.env` **ห้ามใช้บน Vercel**) · ถ้าไม่จำเป็นอย่าใส่แฮชจริงในไฟล์ `.env`
7. อย่าส่งบรรทัดแฮชทางแชต/อีเมล · อย่า commit ลง git

## 4. ผูกโปรเจกต์กับ Vercel (เลือกทางใดทางหนึ่ง)

### ทาง A — ผ่าน Git (แนะนำ: แก้โค้ดแล้ว deploy อัตโนมัติ)
1. ใส่โค้ดขึ้น GitHub/GitLab/Bitbucket (ไฟล์ `.gitignore` กัน `node_modules`, `dist`, `.env` ไว้แล้ว)
2. Vercel → **Add New… → Project** → เลือก repo → **Import**
3. ตั้งค่าตามข้อ 4.1 แล้วกด **Deploy** (ขั้นนี้ยังไม่ต้องกังวลว่าเว็บจะใช้งานได้ — ต้องใส่ env ก่อน ข้อ 5)

### ทาง B — อัปโหลดจากเครื่องด้วย Vercel CLI (ไม่ใช้ git)
1. ในโฟลเดอร์โปรเจกต์รัน `npx vercel` (ครั้งแรกจะให้ล็อกอิน แล้วถามชื่อโปรเจกต์ — ตอบให้ตรงโฟลเดอร์นี้)
2. ขึ้นเว็บจริง (production) ด้วย `npx vercel --prod` หลังตั้ง env เสร็จ (ข้อ 5)
3. ไฟล์ `.vercelignore` ตัด `crypto-matrix/`, `.env*` ออกจากการอัปโหลดแล้ว

### 4.1 ค่าที่ต้องตั้งในหน้า Project

| **Root Directory** | โฟลเดอร์ที่มี `package.json` ของระบบตารางเรียน (ถ้า repo มีหลายโปรเจกต์ เช่น `timetable/` กับ `crypto-matrix/` ให้เลือก **`timetable`** — **ห้ามเลือก `crypto-matrix`**) |

## 5. ตั้ง Environment Variables บน Vercel
Vercel → Project → **Settings → Environment Variables → Add** · ตั้งทีละตัว และเลือก environment (Production / Preview / Development) ให้ถูก

| ตัวแปร | บังคับ | ความหมาย | ตัวอย่างค่า (ไม่ใช่ของจริง) |
|---|---|---|---|
| `UPSTASH_REDIS_REST_URL` | ใช่ | ที่อยู่ REST ของ Upstash (ข้อ 2) | `https://xxxx-12345.upstash.io` |
| `UPSTASH_REDIS_REST_TOKEN` | ใช่ | token เขียน/อ่าน (ความลับ) | `AXxxXX…(ยาว)` |
| `UPSTASH_REDIS_REST_READONLY_TOKEN` | ไม่ | token อ่านอย่างเดียว ใช้กับเส้นทางผู้ชม/ลิงก์ — เขียนไม่ได้แม้โค้ดผิดพลาด | `AYyyYY…(ยาว)` |
| `SESSION_SECRET` | ใช่ | กุญแจเซสชัน ≥ 32 ไบต์ สุ่ม (ข้อ 3.1) | `k3J…(base64url ~64 ตัว)` |
| `ADMIN_ACCOUNTS` | ใช่ | บัญชีแอดมิน (ข้อ 3.2) | `admin:scrypt$32768$8$1$<salt>$<hash>` |
| `ALLOWED_ORIGINS` | ใช่ | โดเมนที่อนุญาตให้ส่งคำขอเขียน/login (คั่น `,`; เทียบ scheme+host+port เต็ม ไม่มี `/` ท้าย) | `https://timetable.example.com` |
| `PUBLIC_RATE_LIMIT` | ไม่ | เพดานคำขอหน้าสาธารณะต่อ IP ต่อนาที (10–100000) ไม่ตั้ง = 300 | `300` |

ข้อควรระวัง:
- **ห้ามตั้งตัวแปรขึ้นต้น `VITE_` เลย** (หน้าเว็บไม่ใช้ตัวแปรใด ๆ ที่ขึ้นต้น `VITE_`; ค่าเหล่านี้จะถูกฝังลงหน้าเว็บที่ทุกคนอ่านได้ — `vite.config.js` ใช้ allowlist ที่ว่างอยู่ จึงทำให้ build ล้มถ้ามี `VITE_*` ที่มีค่า ไม่ว่าชื่ออะไร)
- **Production กับ Preview ต้องใช้คนละค่า:** ฐาน Upstash คนละตัว, `SESSION_SECRET` คนละค่า, `ADMIN_ACCOUNTS` คนละบัญชี/คนละรหัสผ่าน (ห้ามเอารหัสผ่านจริงไปใส่ใน Preview) · URL ของ Preview เปลี่ยนทุก deployment จึงใส่ใน `ALLOWED_ORIGINS` ลำบาก — ใช้ alias คงที่ หรือยอมรับว่า Preview เขียนข้อมูลไม่ได้จนกว่าจะตั้ง
- **เปิด Deployment Protection ให้ Preview** (Settings → Deployment Protection) เพื่อไม่ให้ใครเข้า Preview ที่ต่อฐานทดสอบ
- แก้ env แล้วต้อง **Redeploy** (Deployments → ⋯ → Redeploy) ถึงจะมีผล
- ไม่ต้องตั้ง `VERCEL_ENV` เอง (Vercel ตั้งให้)

## 6. โดเมน และ `ALLOWED_ORIGINS`
1. Vercel → Project → **Settings → Domains → Add** ใส่โดเมนของโรงเรียน แล้วตั้ง DNS ตามที่ Vercel บอก (ถ้ายังไม่มีโดเมน ใช้ชื่อ `https://<ชื่อโปรเจกต์>.vercel.app` ที่ Vercel ให้ได้เลย)
2. ตั้ง `ALLOWED_ORIGINS` เป็นโดเมนที่ผู้ใช้เปิดจริง **ตรงทุกตัวอักษร** เช่น `https://timetable.example.com` (ไม่มี `/` ท้าย; ใช้ https) — มีหลายโดเมน (เช่น ทั้ง `.vercel.app` และโดเมนจริง) คั่นด้วย `,`
3. **Redeploy** แล้วลองเข้าสู่ระบบ — ถ้าล็อกอินได้ 403 แปลว่า origin ไม่ตรงกับที่ตั้งไว้

## 7. ตรวจหลัง deploy (ทำตามลำดับ)
1. เปิดหน้าเว็บ `https://<โดเมน>/` ต้องเห็นหน้าสาธารณะ (ถ้าฐานว่างจะยังไม่มีตาราง)
2. ตรวจว่า API ปิดจากคนไม่ล็อกอิน — ต้องได้ **401** และหัว `cache-control: no-store`:
   ```
   curl -i https://<โดเมน>/api/auth/me
   ```
3. ตรวจหัวความปลอดภัยของหน้าเว็บ — ต้องมี `content-security-policy`, `strict-transport-security`, `x-frame-options: DENY`:
   ```
   curl -sI https://<โดเมน>/
   ```
4. ตรวจหัวของหน้าสาธารณะ (ยังไม่เคยยืนยันบน Vercel — ดูข้อ 14) — คาดว่าได้ `cache-control: no-cache` และมี `etag`:
   ```
   curl -si https://<โดเมน>/api/public
   ```
5. ตรวจว่าความลับไม่หลุดลงไฟล์หน้าเว็บ (รันในเครื่องหลัง `npm run build`) — ต้อง **ไม่เจออะไร**:
   ```
   npm run build
   grep -rE "UPSTASH|SESSION_SECRET|ADMIN_ACCOUNTS" dist/
   ```
6. เข้าสู่ระบบ: เปิด `https://<โดเมน>/#/login` ใส่ username/รหัสผ่านแอดมิน → ต้องเห็นเมนูแอดมิน · ลองรหัสผิด 1 ครั้งต้องได้ข้อความ "ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง"
7. ตั้งค่าโหมดสาธารณะ: เมนู **ตั้งค่า** (ข้อ 11) — ตอนติดตั้งใหม่จะมีแบนเนอร์ "ยังไม่ได้ตัดสินใจเรื่องแสดงชื่อครูต่อสาธารณะ" ให้เลือกและบันทึก
8. ตรวจ IP: ระบบอ่านที่อยู่ผู้เรียกจาก `x-vercel-forwarded-for` → `x-real-ip` → `x-forwarded-for` — ยังไม่ได้ยืนยันบน Vercel จริงว่าค่าเหล่านี้เชื่อถือได้ ถ้าจะตรวจ ลองส่ง `X-Forwarded-For` ปลอมแล้วดูว่าตัวนับ rate limit ยังนับตาม IP จริง
9. ลองส่งออก Excel/PDF และนำเข้า Excel หนึ่งครั้งในเบราว์เซอร์ แล้วเปิด Console (F12) ดูว่าไม่มีข้อความ `Content Security Policy` ปฏิเสธ (CSP ยังไม่เคยลองในเบราว์เซอร์จริง)

## 8. ย้ายข้อมูลเดิมขึ้นระบบ
ระบบใหม่เริ่มจาก **ฐานว่าง** (หลังเข้าสู่ระบบจะเห็นว่าไม่มีข้อมูล) นำข้อมูลเดิมเข้าได้จากไฟล์ JSON (รองรับข้อมูลรุ่น v1–v4 ระบบแปลงเป็นรุ่นล่าสุดให้เอง)

### 8.1 ถ้ามีไฟล์ JSON อยู่แล้ว
เข้าสู่ระบบแอดมิน → เมนู **ข้อมูล** → **นำเข้า JSON…** → เลือกไฟล์ → ตรวจรายงาน (ถ้ามีข้อผิดพลาดระบบแจ้งแถว/สาเหตุและไม่เปลี่ยนข้อมูลเดิม) → ยืนยัน

### 8.2 ถ้าข้อมูลเดิมอยู่ใน localStorage ของเบราว์เซอร์ (โหมดทดลองเก่า)
ข้อมูลโหมดทดลองอยู่ในเบราว์เซอร์ **เฉพาะ origin (โดเมน+พอร์ต) ที่เคยเปิด** จึงต้องเปิดเวอร์ชันเก่าที่ origin เดิมเพื่อส่งออกก่อน:
1. เวอร์ชันเก่าที่ build ไว้สำรองอยู่ที่โฟลเดอร์ `backup-timetable-full-2026-10-13/dist` — **พาธนี้เป็นของเครื่องบอสที่มีโฟลเดอร์สำรองนั้นอยู่** (อยู่ใน `company/` ข้างโฟลเดอร์ `project/`) ถ้าเครื่องอื่นไม่มีโฟลเดอร์นี้ก็ทำข้อ 8.2 ไม่ได้ ให้ขอสำเนาจากบอส
2. เปิดเทอร์มินัลในโฟลเดอร์โปรเจกต์ `timetable` (โฟลเดอร์เดียวกับที่ใช้รันคำสั่งในคู่มือนี้) แล้วรันเว็บเซิร์ฟเวอร์เล็ก ๆ — พาธด้านล่างนับจากโฟลเดอร์ `timetable` ขึ้นไป 2 ระดับ (`../..` = โฟลเดอร์ `company`); ถ้ารันจากที่อื่นให้ `cd` มาที่ `timetable` ก่อน หรือแก้พาธให้ชี้ถึงโฟลเดอร์ `dist` ของไฟล์สำรองให้ถูก — ให้ **ใช้พอร์ตเดิมที่เคยเปิดใช้งาน** (ถ้าเคยเปิดที่ `http://localhost:5173` ให้ใช้ 5173 — พอร์ตต่างกันคือ origin ต่างกัน จะมองไม่เห็นข้อมูลเดิม):
   ```
   npx serve -l 5173 "../../backup-timetable-full-2026-10-13/dist"
   ```
   (ครั้งแรก `npx` จะถามติดตั้งแพ็กเกจ `serve` — ต้องต่ออินเทอร์เน็ต) แล้วเปิด `http://localhost:5173/` ในเบราว์เซอร์/โปรไฟล์ **เดียวกับที่เคยใช้งาน**
3. ถ้าเห็นข้อมูลเดิม = ถูก origin → เมนู **ข้อมูล** → **ส่งออก JSON** จะได้ไฟล์ `timetable-<วันที่>.json` เก็บไว้
4. ถ้าเปิดแล้วว่างเปล่า แปลว่า origin ไม่ตรง (พอร์ต/โดเมน/เบราว์เซอร์/โปรไฟล์ต่างกัน) ลองพอร์ตอื่นที่เคยใช้ — **อย่าล้างข้อมูลเบราว์เซอร์** จนกว่าจะส่งออกสำเร็จ
5. จากนั้นทำตามข้อ 8.1 บนเว็บจริง
- *ข้อสันนิษฐานที่ยังไม่ได้ยืนยัน:* ไฟล์สำรองนั้นรันในโหมดเก็บข้อมูลในเบราว์เซอร์ตามที่ build ไว้ — ผู้เขียนไม่ได้เปิดดูด้วยเบราว์เซอร์จริง

### 8.3 ทางเลือกขั้นสูง: เรียก `/api/migrate` ตรง ๆ
ใช้เมื่อไฟล์ใหญ่หรืออยากแทนที่ทั้งฐาน · ล็อกอินเว็บจริงไว้ก่อน แล้วเปิด Console (F12) ของแท็บนั้น วางโค้ด (แทน `<JSON>` ด้วยเนื้อไฟล์ทั้งก้อน):
```
fetch('/api/migrate', { method: 'POST', headers: { 'Content-Type': 'application/json', 'X-Requested-With': 'tt' }, body: JSON.stringify({ state: <JSON>, force: false }) }).then(r => r.json()).then(console.log)
```
- ฐานว่างได้เลย · ฐานมีข้อมูลแล้วต้อง `force: true` (ระบบถ่าย snapshot ก่อนทับให้) · ใส่ `dryRun: true` เพื่อดูสรุปโดยไม่เขียน · ขนาดไม่เกิน 4 MB

## 9. สำรอง snapshot และกู้คืน
- ก่อนการกระทำที่ทำลายข้อมูล (`/api/migrate` แบบ `force`, นำเข้าแบบแทนที่, ตัดคาบเกิน) ระบบถ่าย **snapshot** ให้อัตโนมัติ เก็บล่าสุด **5 ชุด** หมดอายุ 30 วัน
- ดูรายการ: ล็อกอินอยู่ แล้วเปิด `https://<โดเมน>/api/snapshots` ในแท็บเดียวกัน (ได้รายการ snapshot + audit 50 รายการล่าสุด) · ดาวน์โหลดชุดที่ต้องการ: `https://<โดเมน>/api/snapshots?version=<เลข>`
- **กู้คืน:** เก็บส่วน `state` จาก JSON ของ snapshot แล้วใช้วิธีข้อ 8.3 ด้วย `force: true`
- **สำรองเอง (แนะนำทำเป็นประจำ เช่นก่อนปิดเทอม):** เมนู **ข้อมูล → ส่งออก JSON** เก็บไฟล์ไว้ในที่ปลอดภัย — snapshot ถ่ายเฉพาะก่อนการกระทำทำลายข้อมูล ไม่ใช่สำรองรายวัน
- audit log (`tt:audit`) เก็บ 500 รายการล่าสุด: เวลา, ชื่อผู้ใช้, ชนิดการกระทำ, version, แฮชย่อของ IP — ไม่เก็บรหัสผ่านหรือโทเค็น
- ฟีเจอร์สำรองอัตโนมัติ/Point-in-time ของ Upstash ขึ้นกับแพ็กเกจของ Upstash — ตรวจที่ console ของคุณเอง (ผู้เขียนไม่ได้ตรวจ)

## 10. เปลี่ยนรหัสผ่าน / เพิ่ม-ลบแอดมิน / ลืมรหัสผ่าน
- **เปลี่ยนรหัสผ่าน:** ทำข้อ 3.2 ข้อ 2–4 ใหม่ด้วย username เดิม แล้ว **แทนที่ส่วนของคนนั้น** ในค่า `ADMIN_ACCOUNTS` (ไม่ใช่ต่อท้าย — ถ้าชื่อซ้ำ แม้ต่างตัวพิมพ์ ระบบถือว่าตั้งค่าผิดและ login ตอบ 500 ทุกคนจนกว่าจะแก้) → **Redeploy** → เซสชันเดิมของบัญชีนั้นหลุดทันที บัญชีอื่นไม่กระทบ
- **เพิ่มแอดมิน:** สร้างแฮชของคนใหม่ แล้วต่อท้ายด้วย `;` → Redeploy
- **ลบแอดมิน:** ลบรายการ `user:scrypt$…` ของคนนั้นออกจากค่า → Redeploy → เซสชันเขาใช้ไม่ได้ทันที · อย่าลบจนไม่เหลือบัญชีที่ใช้ได้ (login จะตอบ 500 ทุกคน)
- **ตัดทุกเซสชันทันที** (สงสัยว่าคุกกี้รั่ว): เปลี่ยน `SESSION_SECRET` เป็นค่าสุ่มใหม่ → Redeploy
- **ลืมรหัสผ่าน:** ไม่มีหน้า "ลืมรหัสผ่าน" โดยตั้งใจ (ไม่มีอีเมล/ระบบกู้คืนที่ปลอดภัย) ผู้ดูแลที่เข้า Vercel ได้ทำ "เปลี่ยนรหัสผ่าน" ให้ — **ข้อมูลตารางไม่หาย** (อยู่ใน Upstash คนละที่) · ถ้าเข้า Vercel ไม่ได้เลย ต้องกู้บัญชี Vercel ก่อน
- ข้อควรรู้: ค่า `ADMIN_ACCOUNTS` ที่รายการใดรูปแบบเสีย (เช่นแฮชถูกตัดกลางทาง) จะถูก **ข้าม** พร้อมเขียนเตือนใน Vercel Logs (`[auth] ADMIN_ACCOUNTS: ข้ามรายการที่รูปแบบผิด #ลำดับ (ชื่อ)` ไม่มีแฮช) — บัญชีนั้นเข้าไม่ได้ (ได้ข้อความ "ไม่ถูกต้อง" เหมือนรหัสผิด) แต่บัญชีอื่นยังใช้ได้ · ถ้าเสียทุกรายการ login ตอบ 500
- เซสชัน: หมดอายุเมื่อไม่ใช้ 2 ชั่วโมง และอย่างช้า 12 ชั่วโมงนับจากล็อกอิน

## 11. โหมดสาธารณะและการซ่อนชื่อครู (PDPA)
- **โหมดสาธารณะเปิดอยู่เป็นค่าเริ่มต้น แต่ซ่อนชื่อครูไว้ก่อน** จนกว่าแอดมินจะตัดสินใจเอง: ใครก็ตามที่รู้ URL เห็นตารางทั้งสถานศึกษา (กลุ่มเรียน วิชา ห้อง) โดยไม่ต้องล็อกอิน แต่ **ชื่อครูไม่ถูกส่ง** จนกว่าแอดมินตั้ง "แสดงชื่อครูในโหมดสาธารณะ" เอง · ผู้ชมทั่วไปแก้ไขอะไรไม่ได้
- ตั้งค่าที่เมนู **ตั้งค่า** (มีผลทันที ไม่ต้อง deploy):
  - **เปิด/ปิดโหมดสาธารณะ:** ปิด = หน้าสาธารณะแจ้ง "ผู้ดูแลปิดการเข้าชมสาธารณะ" (ลิงก์แชร์เฉพาะ scope ยังใช้ได้)
  - **แสดง/ซ่อนชื่อครู:** เมื่อซ่อน เซิร์ฟเวอร์ **ไม่ส่งรายชื่อครู รหัสครู แผนก และช่องหมายเหตุ (note) ของวิชา/ห้อง/กลุ่ม** ให้ผู้ชมทั่วไปเลย (ไม่ใช่แค่ซ่อนในหน้า) ผู้ชมจึงไม่มีมุมมองรายครู และไม่เห็นหมายเหตุ · เมื่อแสดง ส่งทั้งหมดตามเดิม
  - แอดมินสองคนบันทึกพร้อมกัน: คนหลังที่ใช้ข้อมูลเก่าจะได้ข้อความให้โหลดใหม่ ไม่ทับกันเงียบ ๆ
- **ปลอดภัยไว้ก่อน:** ถ้าค่าตั้งใน Upstash เสีย/ขาด/ชนิดผิด ระบบถือว่า "ซ่อนชื่อครู" · ถ้าอ่าน Upstash ไม่ได้เลย หน้าสาธารณะตอบ 503 (ไม่ตกไปเป็นแสดงชื่อครู)
- **ข้อจำกัดที่ต้องรู้ (PDPA):**
  - ชื่อครูที่พิมพ์ลงในชื่อวิชา/ห้อง/กลุ่ม (ข้อความอิสระที่ไม่ใช่ช่อง note) ระบบลบให้ไม่ได้แม้ซ่อน — ถ้าต้องการซ่อนจริงต้องไม่พิมพ์ชื่อครูในช่องเหล่านั้น
  - เมื่อ **แสดงชื่อครู** ชื่อครูในช่องข้อความอิสระก็ถูกส่งไปด้วย
  - **ลิงก์แชร์ scope `all`** เห็นชื่อครูทั้งหมดแม้ซ่อนในโหมดสาธารณะ (คนละกลไก) จึงหมดอายุ 90 วันโดยค่าเริ่มต้น (ต่ออายุด้วย "สร้างใหม่") — ถ้าต้องการซ่อนจริง อย่าแจกลิงก์ `all` หรือเพิกถอนที่เมนู **ลิงก์แชร์** · ลบกลุ่ม/ครู/ห้อง = ลิงก์ที่ชี้เอนทิตีนั้นถูกเพิกถอนอัตโนมัติ
- ขีดจำกัดหน้าสาธารณะ: 300 ครั้ง/นาที/IP (ปรับด้วย `PUBLIC_RATE_LIMIT`) เกิน → 429

## 12. ปลดล็อกแอดมินที่ถูก rate limit ล็อก
ตัวนับการเข้าสู่ระบบมี 4 ระดับ ต่อ 15 นาที: IP+username **5** ครั้ง · username รวมทุก IP **20** · IP **30** · ทั้งระบบ **300** เกินแล้วได้ **429** พร้อมหัว `Retry-After` (ตรวจก่อนคำนวณรหัสผ่าน)

ผลข้างเคียงที่รับไว้: ผู้โจมตีที่กระจายหลาย IP **ล็อกแอดมินชั่วคราว** ได้ (แอดมินจริงจะได้ 429) ทางออก:
1. **รอ** ตามเวลาใน `Retry-After` (สูงสุด 15 นาที) ตัวนับหมดอายุเอง
2. **ปลดทันที:** Upstash console → Data Browser/CLI ของฐานข้อมูลนั้น แล้วลบตัวนับ (key เป็นแฮช ระบุ IP/ชื่อตรง ๆ ไม่ได้ จึงลบทั้งกลุ่ม — ปลอดภัย แค่ตัวนับเริ่มใหม่):
   ```
   SCAN 0 MATCH rl:login:* COUNT 1000
   DEL rl:login:all
   ```
   `SCAN` แสดง key: `rl:login:ui:*` (IP+user) · `rl:login:u:*` (user) · `rl:login:ip:*` (IP) · `rl:login:all` (ทั้งระบบ) — `DEL` ทุก key ที่เจอ (วน `SCAN` จน cursor เป็น 0) · ฝั่งผู้ดูลิงก์ `rl:view:ip:*` (120/นาที) และหน้าสาธารณะ `rl:pub:ip:*` ลบด้วยวิธีเดียวกัน
   **อย่าลบ** `sess:*` (ทำให้ทุกคนหลุด) หรือ `tt:*` / `share:*` (ข้อมูลจริง)
3. ถูกโจมตีต่อเนื่อง: เปิด **Vercel Firewall → Rate Limiting** สำหรับ `/api/auth/login` และ `/api/state` ที่ชั้น edge (ตั้งที่ dashboard ไม่ใช่ในโค้ด)

| ขึ้นว่า "ตั้งค่าถูกแก้โดยผู้อื่น" (409) | แอดมินอีกคนบันทึกตั้งค่าไปก่อน | โหลดหน้าใหม่ แล้วบันทึกอีกครั้ง |
| หน้าเว็บ/ส่งออก Excel-PDF ใช้ไม่ได้ มีข้อความ CSP ใน Console | นโยบาย CSP ใน `vercel.json` ปฏิเสธบางอย่าง (ยังไม่เคยลองในเบราว์เซอร์จริง) | จดข้อความ violation ทั้งบรรทัดแจ้งผู้ดูแลโค้ด · **อย่าเปิด `unsafe-inline` ใน `script-src`** |
| `build` ล้มด้วยข้อความ "ขึ้นต้นด้วย VITE_ … ฝังลงบันเดิล" | มีตัวแปรขึ้นต้น `VITE_` (ใน Vercel env หรือไฟล์ `.env`) ที่ไม่อยู่ใน allowlist | ลบตัวแปรนั้น (หน้าเว็บไม่ใช้) ถ้าเป็นความลับต้องเปลี่ยนชื่อให้ไม่มี `VITE_` (ข้อ 5) |
| หน้าสาธารณะแจ้ง "ผู้ดูแลปิดการเข้าชมสาธารณะ" | แอดมินปิดไว้ | เมนู **ตั้งค่า** → เปิดโหมดสาธารณะ |
| หน้าสาธารณะ 503 | อ่าน Upstash ไม่ได้ (ล่ม/token ผิด/โควตาหมด) | ตรวจสถานะ Upstash และ `UPSTASH_REDIS_REST_*` |
| ได้ 413 ตอนบันทึก | ข้อมูลส่วนหนึ่งใหญ่เกิน ~900 KB ต่อหนึ่งรายการ | แบ่งข้อมูล/แจ้งผู้ดูแลโค้ด |
| ได้ 503 `busy` | มีการเขียนแย่งกันหนาแน่น (ลองซ้ำครบ 4 รอบ) | ลองใหม่อีกครั้ง |

## 14. ความปลอดภัยโดยสรุป และความเสี่ยงที่รับไว้
**มีอยู่แล้ว:** รหัสผ่าน scrypt (N=2^15, r=8, p=1) + เทียบแบบ timing-safe · คุกกี้ `__Host-tt_session` (`HttpOnly; Secure; SameSite=Lax`) · เซสชันใน Redis ผูกบัญชี+แฮชรหัสผ่าน (เปลี่ยนรหัส/ลบบัญชี = เซสชันเดิมหลุดทันที) · CSRF (JSON + `X-Requested-With: tt` + Origin ตรง allowlist) · rate limit ก่อนคำนวณรหัสผ่าน · โทเค็นลิงก์แชร์ 256 บิต เก็บเป็น SHA-256 เท่านั้น · ผู้ชมเขียนไม่ได้ทุก endpoint และ response กรองที่เซิร์ฟเวอร์ · ทุกการแก้ตรวจซ้ำที่เซิร์ฟเวอร์ด้วยตรรกะเดียวกับหน้าเว็บ · เขียนด้วย compare-and-set (409 เมื่อมีคนแก้พร้อมกัน) · snapshot + audit · CSP + หัวความปลอดภัย · `Cache-Control: no-store` กับ API (ยกเว้น `/api/public` = `no-cache` + ETag) · ไม่ log body/คุกกี้/โทเค็น

**ความเสี่ยงที่รับไว้ (ต้องรู้):**
1. ผู้โจมตีกระจายหลาย IP ล็อกแอดมินชั่วคราวได้ (ข้อ 12) — ปลดด้วย Upstash console ต้องมีคนที่เข้า console ได้
2. ไม่มีการยืนยันตัวตนสองชั้น และไม่มีนโยบายกันรหัสผ่านอ่อน (ยาว ≥ 10 ตัวเท่านั้น) — เลือกรหัสผ่านดี ๆ
3. ไม่มีหน้ากู้รหัสผ่าน/ไม่มีปุ่ม "ออกจากระบบทุกเครื่อง" (ทำได้ทางเดียวคือเปลี่ยน `SESSION_SECRET`)
4. ลิงก์แชร์ scope `all` และข้อความอิสระที่มีชื่อครูหลุดผ่านทางที่โหมดซ่อนชื่อป้องกันไม่ได้ (ข้อ 11)
5. ถ้า `tt:settings` เสียทั้งก้อน ค่า "เปิด/ปิดโหมดสาธารณะ" กลับเป็น "เปิด" (ชื่อครูยังซ่อน) — แอดมินตั้งใหม่ได้ที่เมนู **ตั้งค่า**
6. ทุกสิ่งที่ยังไม่ได้ยืนยัน (ด้านล่าง)

## 15. สิ่งที่ยังไม่ได้ยืนยัน (ตรงไปตรงมา)
- **ยังไม่เคยรันกับ Upstash/Vercel จริง:** ตัวเชื่อม `@upstash/redis`, Lua `EVAL` จริง, read-only token, เพดานคำขอ 1 MB, `maxDuration`, การแข่งกันข้ามอินสแตนซ์ serverless, header IP ของ Vercel, คุกกี้ `Secure`/`__Host-` บน https
- **หัว `Cache-Control` ของ `/api/public`:** `vercel.json` ตั้ง `no-cache` เฉพาะ path นี้ (และ `no-store` ให้ endpoint อื่น) แต่ยังไม่ได้ลองว่า Vercel ตีความกฎ `source` ตามที่ตั้งใจ — ตรวจด้วยข้อ 7.4 ถ้าไม่ตรง ผลเสียคือแค่ไม่ได้ 304 (ข้อมูลยังถูกต้อง)
- **CSP ไม่เคยลองในเบราว์เซอร์จริง:** `worker-src blob:` เป็นข้อสันนิษฐานจากโค้ด (บันเดิลของไลบรารี Excel มี `new Worker`) · ถ้าส่งออก/นำเข้า Excel พังและมี violation ใน Console ให้แจ้งผู้ดูแลโค้ด
- **Node 22** ที่ Vercel ใช้ ยังไม่ได้รันยืนยัน (ทดสอบบนเครื่องพัฒนาด้วย Node เวอร์ชันใหม่กว่า)
- ขั้นตอนย้ายข้อมูลจาก localStorage (ข้อ 8.2) เขียนจากโครงสร้างโค้ด ยังไม่ได้ลองกับข้อมูลจริงของบอส
- ขั้นตอนบนหน้าเว็บ Vercel/Upstash (ชื่อเมนู/ปุ่ม) อาจต่างจากที่เขียนเมื่อบริการเปลี่ยนหน้าจอ

## 16. (ทางเลือก) ลองรันทั้งระบบบนเครื่องก่อนขึ้นจริง
โปรเจกต์ไม่มีเซิร์ฟเวอร์ในเครื่อง (`api/` ทำงานบน Vercel) ถ้าอยากลองทั้งระบบบนเครื่องใช้ Vercel CLI ภายนอกโปรเจกต์ (ไม่ได้เพิ่มเป็น dependency): `npx vercel dev` พร้อมดึง env ลงเครื่องด้วย `npx vercel env pull .env.local` — ข้อควรระวัง: ต้องตั้ง `ALLOWED_ORIGINS` ให้ตรงกับ origin ที่เปิดในเครื่อง (เช่น `http://localhost:3000`) เอง — ระบบไม่อนุญาต localhost ให้อัตโนมัติ · คุกกี้ `__Host-` ต้องใช้ https ซึ่งใช้ไม่ได้บน `http://localhost` (ผู้เขียนยังไม่ได้ลอง `vercel dev` จริง) ทางที่ง่ายกว่าและตรงกับของจริงที่สุดคือ deploy เป็น **Preview** ที่ต่อฐาน Upstash ทดสอบ (ข้อ 5) แล้วลองที่นั่น
- `npm run build` ในเครื่อง → `dist/` · `npm run preview` ดูหน้าเว็บที่ build แล้ว (เฉพาะหน้า ไม่มี API)
